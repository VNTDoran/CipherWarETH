Cipher War — Smart Contracts

Five contracts sit under the game. The match itself runs off-chain (it ticks ten times a second), so the chain only holds the moments that need trust: the secret key draw, fuel payments, the stake, and the final result. Examples use ethers v6 against the local Hardhat node.

How the pieces fit

Every contract except IntelToken has a fixed gameServer address set at deployment (immutable), and only that address can call its write methods marked server. Reads are open to everyone, which is what lets any player re-verify the server.

1StakePlayers approve then join a TournamentEscrow, locking INTEL.
2DispatchServer calls commitCourier (hash of the secret key) and registerCourier (owner + fuel).
3FlyCourier runs out of fuel and freezes. Its owner pays boost in ETH to restart it.
4ResolveServer calls revealCourier; the chain rejects any value that doesn't match the hash.
5SettlefinalizeMatch anchors the result, settle pays the pot, payBounty pays the fuel ETH.

CommitRevealRegistry

0xe7f1725E7734CE288F8367e1Bb143E90bb3F0512

Every courier carries N candidate decryption keys and exactly one is real. Before the courier can be attacked, the server publishes only keccak256(matchId, courierId, keyIndex, nonce). The hash is binding (no other input produces it, so the answer can't change) and hiding (the random nonce stops anyone from brute-forcing the N possible indexes). At resolution the server reveals the index and nonce, and the contract reverts if they don't hash to the stored commitment.

Without the nonce there would be only N possible hashes, and anyone could hash indexes 0 to N-1 and read the key straight out of the commitment.

Lifecycle (Status enum)

ValueMeaning
0 UnknownNever committed.
1 CommittedCommitment published, courier in flight, reveal still allowed.
2 RevealedRevealed and the hash checked out.
3 DefaultedDeadline passed with no reveal. This is itself public evidence the server failed to prove.

Write methods

commitCourier(matchId, courierId, commitment, candidateCount, revealWindowSeconds)server

Locks in the real key index before the courier is attackable. The hash is computed off-chain, so the preimage never touches the chain. Reverts with AlreadyCommitted on a repeat, IndexOutOfRange if candidateCount is 0, and InvalidWindow if the window is 0 or over 1 hour.

const { id, hexlify, randomBytes } = ethers;
const matchId   = id("CIPHERWAR:ABC123");
const courierId = id("courier-1");
const keyIndex  = 3;                         // secret, picked by the server
const nonce     = hexlify(randomBytes(32));  // secret, kept until reveal

const commitment = await registry.computeCommitment(matchId, courierId, keyIndex, nonce);
await registry.commitCourier(matchId, courierId, commitment, 8, 600); // 8 keys, 10 min window
revealCourier(matchId, courierId, keyIndex, nonce)server

Opens the envelope. Reverts unless the preimage hashes exactly to the stored commitment, so a false reveal cannot even be recorded. Errors: NotCommitted, AlreadyRevealed, RevealWindowClosed, IndexOutOfRange, BadCommitment.

await registry.revealCourier(matchId, courierId, 3, nonce);          // ok

await registry.revealCourier(matchId, courierId, 4, nonce);          // reverts: BadCommitment
// a lie about the key index is rejected by the contract itself

Read methods

computeCommitment(matchId, courierId, keyIndex, nonce) → bytes32view

The exact hash the server must produce. Pure: it reads no state, so anyone can recompute it from revealed values.

const h = await registry.computeCommitment(matchId, courierId, 3, nonce);
courierKey(matchId, courierId) → bytes32view

The storage key keccak256(matchId, courierId). Including matchId means two matches can reuse a courier id without colliding.

getCourier(matchId, courierId) → Courierview

Returns commitment, committedAt, revealDeadline, candidateCount, keyIndex, nonce, revealed. keyIndex and nonce are only meaningful once revealed.

const c = await registry.getCourier(matchId, courierId);
console.log(c.revealed, c.keyIndex, c.candidateCount);
statusOf(matchId, courierId) → Statusview

Lifecycle state, including the silent-server case (Defaulted).

const s = await registry.statusOf(matchId, courierId);   // 0n..3n
if (s === 3n) console.log("server never revealed — evidence of failure");
isProven(matchId, courierId) → boolview

Independently re-hashes the stored preimage and compares it to the stored commitment. It cannot return false after revealCourier succeeds, but it lets a verifier avoid taking that on faith. The /chain page does this check in your browser.

committedCount(matchId) / revealedCount(matchId) → uint32view

Counters for the UI, such as "12 of 14 couriers proven this match".

gameServer() → addressview

The only address allowed to commit and reveal.

Events

CourierCommitted(matchId, courierId, commitment, candidateCount, revealDeadline)
CourierRevealed(matchId, courierId, keyIndex, nonce)

CourierFuel

0xCf7Ed3AccA5a467e9e704C703E8D87F634fB0Fc9

A courier is effectively a transaction. It leaves with a small fuel budget and, when that runs out, it freezes mid-flight, still fully attackable. The owner restarts it only by paying ETH with boost(). The ETH is not burned: it accumulates into a per-match bounty paid to the winner.

The total fuel a courier demands is hidden. It is derived from the courier's secret preimage, so the owner buys a chunk and watches whether it moves, like discovering a transaction's real gas cost. After the reveal anyone can recompute it and prove the server did not inflate the bill.

Constants

NameValueMeaning
FUEL_UNIT_PRICE0.001 ETHPrice of one fuel unit.
SECONDS_PER_UNIT5Seconds of travel per unit.
MAX_UNITS_PER_BOOST6Cap per transaction, so nobody buys out all tension.
MIN/MAX_REQUIRED_UNITS4 / 15Range of the hidden fuel demand.

Write methods

registerCourier(matchId, courierId, owner, unitsAtDispatch, requiredUnits)server

Records who may refuel the courier and how far it flies unaided. requiredUnits must be 4 to 15 (BadRequirement otherwise) and is derived by the server from the secret preimage. Reverts on a repeat (AlreadyRegistered) or zero owner.

const required = await fuel.deriveRequiredUnits(matchId, courierId, keyIndex, nonce); // e.g. 9
await fuel.registerCourier(matchId, courierId, player1Address, 4, required);
boost(matchId, courierId) payablecourier owner

Refuels a stalled courier. Only the registered owner may call it, and the ETH sent must buy between 1 and 6 units (msg.value / 0.001 ETH, rounded down). Adds to the bounty and emits CourierBoosted, which the server listens for before resuming travel.

Errors: UnknownCourier, CourierAlreadyLanded, NotCourierOwner, NoValueSent, TooMuchFuel.

const value = await fuel.quote(3);                    // 3 units = 0.003 ETH
const tx = await fuel.connect(player1).boost(matchId, courierId, { value });
await tx.wait();

await fuel.connect(player2).boost(matchId, courierId, { value }); // reverts: NotCourierOwner
await fuel.connect(player1).boost(matchId, courierId, { value: ethers.parseEther("0.01") });
                                                      // reverts: TooMuchFuel (10 units > 6)
markLanded(matchId, courierId)server

Marks the courier finished so it can no longer be boosted.

await fuel.markLanded(matchId, courierId);
payBounty(matchId, winner)server

Sends all the ETH collected from boosts in this match to the winner. Once only (BountyAlreadyPaid), and reverts with NothingToPay if no one ever boosted.

await fuel.payBounty(matchId, winnerAddress);
console.log(await fuel.bountyPaid(matchId));   // true

Read methods

quote(units) → uint256view

Cost in wei for a number of units, used by the UI to fill in the transaction value.

ethers.formatEther(await fuel.quote(6));   // "0.006"
isStalled(matchId, courierId) → boolview

True while the courier is registered, not landed, and still owed fuel. Note the real answer is hidden from the player in the UI, but it is public on-chain.

unitsOutstanding(matchId, courierId) → uint32view

Units still owed before the courier can finish. Zero means it can fly to the end.

travelSecondsOf(matchId, courierId) → uint32view

Total seconds of travel paid for so far: (unitsAtDispatch + unitsBoosted) × 5.

deriveRequiredUnits(matchId, courierId, keyIndex, nonce) → uint32view

The fuel demand implied by a courier's secret preimage: 4 + keccak("FUEL", …) % 12. Pure and public.

fuelWasHonest(matchId, courierId, keyIndex, nonce) → boolview

After a reveal, checks that the registered requiredUnits equals what the draw dictated. A server that billed more is caught here, the same way one that swapped the key is caught by CommitRevealRegistry.

const c = await registry.getCourier(matchId, courierId);
const honest = await fuel.fuelWasHonest(matchId, courierId, c.keyIndex, c.nonce);
getCourier(matchId, courierId) → Courierview

owner, unitsAtDispatch, unitsBoosted, requiredUnits, boostCount, registered, landed.

bounty(matchId) / bountyPaid(matchId)view

ETH waiting for the winner, and whether it was already paid.

IntelToken (INTEL)

0x5FbDB2315678afecb367f032d93F642f64180aa3

The in-game currency as a real ERC-20, built on OpenZeppelin, so it can be staked and shows up in MetaMask. Intel balances during a match stay off-chain (they change several times a second); this token is the settlement layer. It also has a rate-limited public faucet so every imported demo account can get tokens without the owner minting for each.

It exposes the standard ERC-20 interface (transfer, approve, transferFrom, balanceOf, allowance, totalSupply, 18 decimals) plus:

Constants

FAUCET_AMOUNT1,000 INTEL per claim
FAUCET_COOLDOWN1 minute per address
Initial supply1,000,000 INTEL minted to the owner (the game server)

Write methods

faucet()anyone

Mints 1,000 INTEL to the caller. Reverts with FaucetCooldown(availableAt) if called again within a minute. The first call is always allowed.

await token.connect(player1).faucet();
ethers.formatEther(await token.balanceOf(player1.address));   // "1000.0" (plus any earlier balance)
await token.connect(player1).faucet();                         // reverts: FaucetCooldown
mint(to, amount)owner only

Owner mint, used by deployment scripts to seed accounts. The owner is the game server account.

await token.mint(player3.address, ethers.parseEther("5000"));

Read methods

Seconds before this address can claim again, or 0 if it can claim now. The UI uses it to disable the button.

lastFaucetAt(address) → uint256view

Timestamp of that address's last claim, or 0 if it never claimed.

FaucetClaimed(to, amount) plus standard Transfer / Approval

TournamentEscrow

0xDc64a140Aa3E981100a9becA4E685f962f0cF6C9

Players stake INTEL on a match and the winner takes the pot. This is where commit-reveal earns its keep: once value is at stake, "trust the server" isn't acceptable. If the server settles before settleDeadline, the winner is paid. If it stays silent past the deadline, every player reclaims their own stake and the server gains nothing, so refusing to settle is no longer a free way out of a match it was losing.

States

0 NoneNever created.
1 OpenAccepting stakes.
2 LockedMatch in progress, no more joins. A full table locks itself.
3 SettledWinner paid.

Write methods

createTournament(matchId, stake, maxPlayers, joinWindowSeconds, settleWindowSeconds)server

Opens a tournament. Needs a non-zero stake, 2 to 4 players and non-zero windows (BadParameters), and the match must be new (AlreadyExists). The settle deadline is the join deadline plus the settle window.

await escrow.createTournament(
  matchId,
  ethers.parseEther("100"),   // 100 INTEL each
  4,                          // up to 4 players
  120,                        // 2 min to join
  1800                        // then 30 min for the server to settle
);
join(matchId)player

Stakes and takes a seat. The caller must approve the escrow first (the standard two-step ERC-20 flow, which is why MetaMask prompts twice). Errors: WrongState, JoinClosed, AlreadyJoined, TournamentFull. The last seat auto-locks the tournament.

const stake = ethers.parseEther("100");
await token.connect(player1).approve(escrowAddress, stake);   // step 1
await escrow.connect(player1).join(matchId);                  // step 2 — pulls 100 INTEL
lock(matchId)server

Closes joins early, for example when a 3-player match starts at a 4-seat table. Needs at least 2 players.

await escrow.lock(matchId);
settle(matchId, winner)server

Pays the whole pot to the winner, who must have joined (WinnerNotPlaying). Only valid while Locked and before the settle deadline (SettleWindowClosed); after that the players' refund right takes precedence.

await escrow.settle(matchId, winnerAddress);   // 4 players × 100 = 400 INTEL to the winner
claimRefund(matchId)player

If the server never settled, each player takes back their own stake. Only after the settle deadline (SettleWindowOpen before that), only for players who joined (NotAPlayer), and once each (AlreadyRefunded).

if (await escrow.refundAvailable(matchId)) {
  await escrow.connect(player2).claimRefund(matchId);   // gets exactly their 100 back
}

getPlayers(matchId) → address[]view

Everyone who staked, in join order.

refundAvailable(matchId) → boolview

hasJoined(matchId, address) / hasRefunded(matchId, address) → boolview

Per-player flags.

How the game uses it

  1. Lobby opens — the server calls createTournament (4 seats, 30 min to join, 1 h to settle). The stake is CHAIN_STAKE_INTEL in .env, 100 INTEL by default.
  2. Players stake from the lobby's buy-in panel: approve then join. The server learns of it from the PlayerJoined event. Nobody can ready up without a stake, and the host can't start until every player in the lobby has staked.
  3. Start — the server calls lock (a full table of 4 has already locked itself).
  4. Finish — the server calls settle for the winner, who takes the whole pot. This is also how a forfeit works: the forfeiter's stake stays in the pot and goes to whoever is left.
Leaving the lobby after staking does not return the stake, because the contract only refunds after the settle deadline. If the server never settles, claimRefund gives every player their own stake back after the deadline. The game server is trusted to name the right winner; the refund path is the safeguard if it stays silent.

MatchRegistry

0x9fE46736679d2D9a65F0992F2272dE9f3c7fa6e0

Anchors finished matches so the leaderboard can't be rewritten. One write per match, not per action. It stores who won, how, and each player's score line, and it keeps career totals up to date as it goes so reads stay cheap.

winType codes

0OPERATION — completed all steps
1BLACKOUT — enough cracks to expose the network
2TIMEOUT — led the board when time expired
3FORFEIT — every rival forfeited (stored as a plain number, so no redeploy was needed)

Write methods

finalizeMatch(matchId, winnerSlot, winType, durationSeconds, results[])server

Records the result once. Each results entry is { player, slot, directivesConfirmed, cracksMade, finalIntel }. It increments played and totalCracks for every player and wins for the one in winnerSlot. Errors: AlreadyFinalized, NoPlayers, WinnerNotPlaying.

await matchRegistry.finalizeMatch(matchId, 0, 0, 412, [
  { player: p1, slot: 0, directivesConfirmed: 5, cracksMade: 2, finalIntel: 640 },
  { player: p2, slot: 1, directivesConfirmed: 3, cracksMade: 4, finalIntel: 310 },
]);   // winner = slot 0 by OPERATION in 412 s

await matchRegistry.finalizeMatch(matchId, 0, 0, 412, [...]);   // reverts: AlreadyFinalized

Read methods

getMatch(matchId) → Matchview

matchId, winnerSlot, winType, finalizedAt, durationSeconds, exists.

const m = await matchRegistry.getMatch(matchId);
if (m.exists) console.log("winner slot", m.winnerSlot, "type", m.winType);
getResults(matchId) → PlayerResult[]view

Every player's score line for that match.

matchCount() / matchAt(i)view

Enumerate every finalized match.

const n = await matchRegistry.matchCount();
for (let i = 0n; i < n; i++) console.log(await matchRegistry.matchAt(i));
wins(address) / played(address) / totalCracks(address) → uint32view

Career totals per wallet, derived on write.

const [w, p] = [await matchRegistry.wins(p1), await matchRegistry.played(p1)];
console.log(`${w}/${p} wins`);

Events

MatchFinalized(matchId, winner, winnerSlot, winType, durationSeconds)

Conventions and setup

Identifiers

matchId and courierId are bytes32 values. The game derives the match id from the join code with keccak256 of "CIPHERWAR:<CODE>", and every contract mixes it into its storage keys so ids never collide across matches.

Connecting

const provider = new ethers.JsonRpcProvider("http://192.168.1.173:8545");   // chain id 31337
const server   = new ethers.Wallet(SERVER_KEY, provider);                    // account #0
const registry = new ethers.Contract(commitRevealAddress, abi, server);

ABIs and addresses are written to public/cipherchain-info.json by npx hardhat run scripts/deploy.js --network localhost.

Errors

The contracts use custom errors (for example BadCommitment, NotGameServer) rather than revert strings. They are cheaper, and ethers decodes them by name when you pass the ABI.

Caveats

  • These addresses are only valid for the current local deployment; restarting the Hardhat node wipes the chain and you must redeploy.
  • The contract proves the server did not change the key. It does not prove the initial draw was uniformly random; that would need player-contributed randomness or a VRF.
  • The server account uses Hardhat's public test key. Treat everything here as a demo, not for real funds.
